# Class Adviser's Portal

## Start the portal

The portal uses its Node.js backend and a database. It defaults to local SQLite; configure `SUPABASE_DB_URL` to store portal records in Supabase PostgreSQL. Do not use VS Code Live Preview to run the application.

1. Double-click `start-portal.bat`. On the first run it checks Node.js and installs dependencies from `package-lock.json` when needed. Alternatively, open a terminal in this folder, run `npm ci`, then run `npm start`.
2. Keep the terminal window open while using the portal.
3. Open the address printed for the portal you need. The teacher, parent, and admin websites each run as a separate server on ports `3004`, `3005`, and `3006`. All three forward API requests to one shared backend on port `3003`.

`npm start` launches four Node.js processes: one shared API/database backend and three separate frontend servers. The default URLs are `http://127.0.0.1:3004` (Teacher Portal), `http://127.0.0.1:3005` (Parents Portal), and `http://127.0.0.1:3006` (Admin Portal). The Admin Portal requires an existing administrator account. The pages share the same API, account/session system, and database; frontend API requests are reverse-proxied to the backend so browser requests remain same-origin.

Sign-in and registration are separated by portal: teachers register and sign in only through the Teacher Portal, and parents/guardians do so only through the Parents Portal. Each portal uses its own session cookie even though local browser cookies are shared across ports. The Admin Portal is sign-in only; admin accounts cannot be self-registered and must be created or granted by an existing administrator.

For initial setup, a private environment file outside synced folders can provide `ADMIN_EMAIL` and `ADMIN_PASSWORD`; set `PORTAL_ADMIN_SECRET_FILE` to its path. On the first API request, the backend creates or grants that administrator account and stores only a bcrypt hash with cost 12. First sign-in is restricted until the temporary password is changed to one of at least 12 characters. Administrator password resets and changes also use bcrypt cost 12; legacy PBKDF2 administrator hashes are upgraded after a successful sign-in. Then delete the private credential file and remove `PORTAL_ADMIN_SECRET_FILE`. The portal cluster does not pass the database URL or bootstrap credentials to frontend processes.

Ports can be changed with `PORTAL_API_PORT`, `PORTAL_TEACHER_PORT`, `PORTAL_PARENTS_PORT`, and `PORTAL_ADMIN_PORT`. The API service can also be started separately with `npm run start:api`; start one frontend separately with `npm run start:teacher`, `npm run start:parents`, or `npm run start:admin`. When running a frontend separately, set `PORTAL_API_URL` if the API is not at `http://127.0.0.1:3003`. For desktop use, `npm run desktop` continues to run the integrated local portal.

## Install as a Windows desktop app

Run `npm ci`, then `npm run dist:win` on a Windows computer. The app executable, installer, and uninstaller use `icon.png` (converted to the required Windows `icon.ico` for packaging). The installer is created at `release/AVeRA Setup 1.0.20.exe`. Run that installer and follow the prompts; the installed app starts the local portal and opens it in its own desktop window without requiring a separately installed Node.js runtime.

The desktop app stores its SQLite database and profile images in the current Windows user's application data folder. Back up that folder to preserve portal records. The installer does not include the live database or `.env` credentials. To launch the app during development, run `npm run desktop`.

The desktop app allows only one running instance so it cannot launch competing local database connections. Database request errors are logged to `%APPDATA%\grade5-class-portal\logs\portal-server.log`; the error message includes a reference ID to locate the corresponding entry. SQLite waits up to 30 seconds for a busy database before returning a lock error.

In the packaged desktop app, generated SF8 reports are saved to `%USERPROFILE%\Downloads\generated-reports` because the application bundle is read-only. When running the development server directly from the project folder, generated reports are saved to `downloads/generated-reports` in the project.

If you already had the portal running when code was updated, stop that old Node server and start it again. A running Node process keeps its old API routes in memory even though it may serve an updated `index.html` from disk. The import button posts to `POST /api/students/import` on the same origin as the portal page; do not change the port manually or open the page using Live Preview.

On a new computer, install Node.js 22.5 or newer and start the portal with `start-portal.bat`, or run `npm ci` followed by `npm start` from this folder. The Node.js built-in `node:sqlite` module is used for the local database option; no separate SQLite server or Express installation is needed.

### If the browser cannot connect

- Start the app with `start-portal.bat` or `npm start` from the folder containing `server.js`; keep that terminal open.
- Open the portal URL printed at startup: teacher `http://127.0.0.1:3004`, parents `http://127.0.0.1:3005`, or admin `http://127.0.0.1:3006`. Visit `http://127.0.0.1:3003/api/health` to check the shared backend. A healthy local backend returns `{"status":"ok","storage":"sqlite"}`; a healthy Supabase backend returns `{"status":"ok","storage":"supabase"}`. If a portal cannot reach the API, confirm all four server processes are running and that `PORTAL_API_URL` points to the shared backend.
- Without Supabase, the first application request creates the SQLite database and migrates an available workbook. With Supabase, it migrates the existing local SQLite database when available, otherwise the selected workbook or default template. Existing account, learner, grade, and attendance data is not included in the GitHub repository.
- If `/api/health` returns an error, check the server terminal for the database connection or migration error. For SQLite, confirm the template workbook is present and the folder is writable. For Supabase, verify `SUPABASE_DB_URL` and that the database is reachable. Set `PORTAL_MIGRATION_WORKBOOK` to import a specific workbook.
- All four servers bind to `127.0.0.1` by default for local use. Public binding is refused unless both `PORTAL_TLS_KEY` and `PORTAL_TLS_CERT` point to a trusted TLS private key and certificate; then set `HOST=0.0.0.0`. The servers use HTTPS and mark session cookies `Secure`. GitHub Pages cannot run this Node.js backend.
- Sign-in is throttled after 10 failed attempts for the same email address or 40 failed attempts from the same source IP within a rolling 15-minute window. These limits are held in process memory and reset when the server restarts. When using a reverse proxy, requests share the proxy's source-IP limit unless `PORTAL_TRUST_PROXY=true` is set behind a trusted TLS-terminating proxy; then the last `X-Forwarded-For` value is used as the client address.

## PostgreSQL and offline synchronization

Neon and other plain PostgreSQL providers work too: paste the pooled connection string into `SUPABASE_DB_URL`.

1. In Supabase, open **Project Settings → Database → Connection string** and copy a PostgreSQL connection string. Use the exact transaction pooler connection string shown for your project when deploying on a hosting provider.
2. Copy `.env.example` to `.env`, set `SUPABASE_DB_URL` to that connection string, and set `PORTAL_STORAGE_MODE=dual`. Keep the database password private; do not put the connection string in browser code or commit `.env`.
3. Run `npm start`. The backend keeps SQLite as the local source of truth and synchronizes saved portal workbook data to PostgreSQL when connected. The local portal remains usable while the online database is unavailable; changes stay queued and retry every 15 seconds. The health endpoint reports the current sync state.

The first empty PostgreSQL database is seeded from the local SQLite state. PostgreSQL transactions use row locking and a revision check. If two offline installations diverge, synchronization pauses and preserves both the local and online workbook snapshots; it does not silently overwrite either. An administrator can inspect `GET /api/admin/sync/status`, then resolve a conflict with `POST /api/admin/sync/resolve` and JSON `{"resolution":"local"}` or `{"resolution":"online"}`. If the online revision changes while a conflict is being reviewed, resolution returns `409` and preserves the newer copy for another review.

Without `PORTAL_STORAGE_MODE=dual`, setting `SUPABASE_DB_URL` retains the existing PostgreSQL-only mode. With no connection URL, SQLite-only mode remains unchanged. PostgreSQL connection credentials stay server-side; TLS certificate verification is required by the connection pool.

## Deploy online (Neon + Render)

1. Create a Neon project and copy its **pooled** connection string (`...-pooler...neon.tech/...`).
2. Push this repository to GitHub, then in Render choose **New → Blueprint** and select the repository. `render.yaml` defines one `advisers-portal` web service that runs the API (loopback only) and serves all three portals via `render-start.js`.
3. When prompted, enter `SUPABASE_DB_URL` (the Neon string) and, for first-time setup, `ADMIN_EMAIL` and `ADMIN_PASSWORD` (a temporary password of at least 12 characters you will change at first sign-in; remove both variables afterwards).
4. After the deploy, open `https://<service>.onrender.com/api/health`; it should return `{"status":"ok","storage":"supabase"}`.
5. Portals: teacher `https://<service>.onrender.com/`, parents `/parents`, admin `/admin`. Cookies are kept separate per portal.

### Synchronize Data Online (local copy ↔ hosted database)

To use the teacher portal's **Synchronize Data Online** button on a local computer, add `PORTAL_STORAGE_MODE=dual` and the same Neon `SUPABASE_DB_URL` to the local `.env` and restart. The button pulls newer online changes and pushes pending local changes. If both copies changed independently, sync pauses and an administrator chooses **Keep local** or **Keep online** in Settings. The first sync of an existing local database against a fresh online database will show this choice: pick **Keep local** to upload your existing records. The hosted Render service itself must not use `dual` mode.

`PORTAL_TRUST_PROXY=true` (set by `render.yaml`) is for TLS-terminating proxies only. Render's free tier sleeps after inactivity, so the first request can take about a minute. Do not set `PORTAL_STORAGE_MODE=dual` on the hosted service.

The Supabase connection role needs permission to create/update the portal tables and add the `revision` column. The setup revokes table access from `anon` and `authenticated` roles. Use a server-side database role, not a browser-facing anon or service-role key.

**Offline synchronization scope:** the synchronized workbook contains accounts, class/learner records, grades, assessments, and attendance. Teacher profile pictures and school-logo files remain in the local profile folders in dual mode and are not currently queued for offline synchronization.

### Deployment security checklist

- Replace the example connection URL with a private PostgreSQL connection string stored only in the server's environment.
- Use a dedicated database role with only the required schema/table permissions; keep database TLS certificate verification enabled.
- Configure the portal's HTTPS certificate and reverse proxy before exposing the portals publicly. Do not expose the database port or connection URL to browsers.
- Restrict access to local SQLite/profile folders and encrypt device storage and backups.
- Back up both the PostgreSQL database and each device's SQLite database. Review `/api/admin/sync/status` and resolve any `conflict` state before treating devices as synchronized.
- The application has server-side validation, parameterized SQL, backend role checks, and sign-in throttling. Existing teacher and parent hashes use PBKDF2-SHA-256; administrator hashes use bcrypt cost 12. The workbook is a single shared state blob rather than tenant-keyed PostgreSQL rows, so PostgreSQL row-level tenant policies are not implemented by dual mode.

## SQLite backend

Without `SUPABASE_DB_URL`, the portal stores live data in `grade5-portal-database.sqlite` in this application folder. On first start it migrates a workbook into SQLite and leaves the workbook unchanged as a backup. If the application workbook is missing, it checks the Downloads database and then the legacy template. Set `PORTAL_DATABASE_PATH` to use a different SQLite file; set `PORTAL_MIGRATION_WORKBOOK` to choose a workbook for a new database.

The SQLite database contains accounts, roster, grades, E-Class records and locks, attendance, and sign-in history. Keep it with the app and include it in regular backups. No demo accounts, students, or grades are added during migration.

### Protecting portal data and backups

The application does not encrypt the SQLite database, workbook files, or local profile-image folders. These can contain learner identifiers, birthdates, grades, attendance, assessment results, and password hashes. `.gitignore` prevents selected files from being committed by Git; it does not prevent OneDrive or another sync client from uploading them. When running the Node server directly with `npm start`, set `PORTAL_DATABASE_PATH` to a protected folder outside the project or any automatically synced folder. The desktop app stores its database under the current Windows user's application data folder.

Enable Windows Device Encryption or BitLocker on computers that store portal data, restrict access to the Windows account, and encrypt removable/off-device backups. To manually back up SQLite safely, stop the portal first, then copy the database and any adjacent `*.profiles` and `*.profiles.school-logos` folders; include SQLite `-wal` or `-shm` sidecars if they remain after shutdown. Keep backups private, and periodically test restoring a copy rather than using the only backup.

The sign-in and sign-up page is for teachers only; parent sign-in and sign-up options have been removed. Teachers select their grade level when signing up; the portal assigns a unique classroom number and parent join code automatically, then displays the join code after registration and on future teacher sign-ins. The classroom number can be changed later in Teacher Profile. Existing parent accounts and linked learner data are retained. Teachers can select **Refresh roster** on the student list to reload available parent accounts before linking them to learners.

Classroom subject lists are selected from the registered grade level in E-Class, subject settings, Term Grade, grade summaries, and linked parent grade records. Grade 1 uses Language, Reading and Literacy, Mathematics, Makabansa, and GMRC (Good Manners and Right Conduct). Grade 2 uses English, Literacy, Mathematics, Makabansa, and GMRC; Grade 3 uses English, Filipino, Mathematics, Science, Makabansa, and GMRC. Grades 4–5 use English, Filipino, Mathematics, Science, Araling Panlipunan, EPP, MAPEH, and GMRC; Grade 6 uses the same areas with TLE in place of EPP. Grades 7–10 use English, Filipino, Mathematics, Science, Araling Panlipunan, MAPEH, one TLE subject category, and Values Education / GMRC. Grade 11–12 registration requires a strand. STEM, ABM, HUMSS, and GAS receive their mapped strand subjects in addition to the Core Subjects; TVL, Arts and Design, and Sports currently use Core Subjects only because their specialized subjects depend on the specific specialization. E-Class grade syncing maps each displayed subject to that registered grade's corresponding grade record when **Save & Lock Record** is selected. The grade-to-subject lists are validated by the server before grades or E-Class records are saved. Sources: [DepEd Revised K to 10 Curriculum](https://www.deped.gov.ph/revised-k-to-10-curriculum/) and [DepEd Orders, including the Strengthened Senior High School Curriculum (DO 017, s. 2026)](https://www.deped.gov.ph/category/issuances/deped-orders/).

On an account's first sign-in in a browser, the portal displays an **About this app, disclaimer & terms** notice before classroom information is shown. The acknowledgment is saved in that browser for that account; signing out does not reset it. The notice may appear again in another browser or after browser storage is cleared.

The teacher navigation includes **Settings** after **Teacher Profile**. Under **Appearance**, choose **Use device setting**, **Light**, **Dark**, or one of 20 additional color themes. The preference is restored after sign-out and sign-in. The desktop app saves it in the user's application data folder, so it also survives app restarts; the browser version keeps it in browser storage. **Performance mode** in Settings reduces shadows, transitions, and background effects to make the interface feel more responsive on slower devices. Its setting is saved in browser storage and does not change portal data or features.

The retained **Parent Portal** displays class and adviser information plus the profile, saved attendance, term grades, BOSY/MOSY/EOSY reading history, and PHIL-IRI results for learners explicitly linked to a parent account. Existing authenticated parent sessions may continue using it, but parents can no longer sign in or sign up from the portal's authentication page. Reading history includes the numbered attempt history and automatically recorded dates. PHIL-IRI results show the GST score and pass status, oral and silent reading levels and measures, and intervention information recorded by the teacher. The parent Reading Progress area has a period comparison graph for legacy reading levels and a separate chronological graph plotting each dated legacy attempt. Reading Progress refreshes when opened and also has a manual refresh button so newly saved teacher assessments appear without signing in again. A collapsible **Sections** hamburger menu appears in the left sidebar directly above **Sign out**, outside the learner information cards, and navigates to Student's Information, Attendance, Reading Progress, and Term Grades. On narrow screens, the sidebar can be opened from the top-bar menu. Parent term grades display Terms 1–3 side by side, with an **Average** column averaging all three terms for each subject. The bottom-right **General Average** cell averages the eight core subjects (including MAPEH, but excluding Music and Arts and Physical Education and Health as separate subjects) across all three terms. It appears only when all core grades for all terms are available; no term-specific General Average values are shown in the footer. Parents cannot browse the class roster or access another learner's records. From **List of Students**, teachers can choose a registered parent from the **Parent account** dropdown for each learner, or choose **Not linked** to remove the link. The dropdown only includes active parent accounts registered with that teacher's class.

## Importing an SF1 roster

To create a section from an SF1 roster, choose **Add New Section**, attach the `.xls` or `.xlsx` file, and press **Add Section**. The portal reads the Grade Level and Section metadata from the SF1 header, saves the new section and its grade, and imports the roster into it together. If either value is missing from the file, enter it in the form as a fallback. The filename and extension do not matter; the portal identifies supported Excel workbooks from their file contents, then checks for the SF1 register headings. It reads student rows with a 12-digit LRN, name in `Last Name, First Name, Middle Name` order, sex, and birth date. It also imports mother tongue, ethnic group, religion, address, father's name, mother's maiden name, and guardian relationship when present. Only these student roster fields are imported; school details, totals, legends, and other workbook content are ignored. The uploaded file is processed locally by the portal and is not saved as an upload. The API returns a clear error for an unsupported or unreadable workbook rather than a generic route error.

LRNs already in that class roster (or repeated in the file) are skipped. Rows with missing or invalid required information are skipped and listed in the import result; other valid rows are still imported. Import accepts files up to 10 MB and up to 1,000 student rows.

Teachers can choose a section from the **Select section** dropdown and press **Select** to apply and lock that section across the student roster, attendance, grades, E-Class, PHIL-IRI, reading, RMA, and nutritional-status learner lists, reports, and generated forms. Press **Change Section** to unlock the dropdown and apply another section. The PHIL-IRI school-consolidated report remains school-wide. **Clear List** and **Clear Month Attendance** require **All sections** because they clear class-wide records. Add students or import a new SF1 while a section is selected to assign them to that section. Students already in the roster are assigned to the current Teacher Profile section the first time the updated roster is loaded; students without a section remain available under **Unassigned**.

In **E-Class**, completed subject calculations apply the DepEd Order No. 015, s. 2026 transmutation table to the initial grade before displaying the Term Grade. Select **Save & Lock Record** to store the highest possible scores, learner scores, and calculated Term Grades in the backend and lock that selected term, subject, section, and MAPEH group. To correct a saved record, select **Unlock to Edit**, enter the teacher password, then save and lock again. The E-Class page links to the [transmutation table reference](https://toolism.app/tools/deped-transmutation-table). **Download E-Class** exports the selected record as an Excel workbook based on the project's `E-CLASS.xlsx` template. The original workbook layout, formatting, data-validation rules, images, and print setup are retained, and school and teacher profile details are added to the record.

The **List of Students** page includes **Clear List** for teachers who need to empty their class roster. The teacher must enter the current account password and then confirm deletion. This permanently removes that class's students and their grades, attendance, and reading assessments; parent accounts and class settings are retained.

## Term grades

Teachers can open **Term Grade** from the hamburger navigation, choose one of the three terms (Term 1, Term 2, or Term 3) and a student, then enter subject grades from 0 to 100. **Save Grades** stores and locks grades for the selected student and term. Select **Edit Grades** to make that student's grades editable again; saving the changes locks them again. Each student's lock is independent, stored in the `Term Grade Locks` worksheet, remains available after a server restart, and is enforced when grades are saved. Legacy term-wide locks are cleared rather than applied to all students because they do not identify a specific learner. Entered grades are stored in the `Term Grades` worksheet. MAPEH is calculated as the average of the Music and Arts and Physical Education and Health grades; both component grades must be entered for the average to appear. General Average is the average of Filipino, English, Mathematics, Science, Araling Panlipunan, GMRC/Values Education, EPP/TLE, and MAPEH. It appears once all eight grades are available and does not count Music and Arts or Physical Education and Health separately. **Print SF9** opens an A4 landscape preview with learning areas matched to the teacher's registered Grade 1–10 curriculum. A school year is optional; if it is not set in Teacher Profile, the SF9 school-year field and attendance totals remain blank. The preview defaults to **All Without Attendance**, showing the full report while omitting numerical attendance values. Choose **All with Attendance** to print the entire SF9 including those values. Choose **Term 1**, **Term 2**, or **Term 3** to show that term's grade values on a blank sheet in their original SF9 cells. Term 3 also includes Final Grades, Remarks, and General Average in their original cells. Choose **Attendance** to show only attendance numbers in their original SF9 cells. In the preview, **Print All** opens print previews for every learner in the teacher's roster using the currently selected print option, with one SF9 per page. In focused selections, all other report text, borders, fills, and logos are hidden without moving any cells. The complete report is automatically scaled to use the full A4 page, with zero configured page margins; merged-cell borders and text are retained. Actual printer margins may vary by device. Select **Print** in the preview to open the browser's print dialog. Set Grade in Teacher Profile first; save any grade edits before previewing. Parents cannot view or change teacher grade records.

Teacher comments can also be saved for each learner and term alongside their grades. The comment editor includes grouped academic-performance, conduct, attendance, and Filipino suggestions. Add one or more suggestions to the comment, then edit or personalize the text before saving. Comments are limited to 1,000 characters; characters that Excel cannot represent are removed so the downloaded workbook remains valid. Comments remain available when grades are reloaded and follow the same grade lock as the associated record. Saved comments appear inside the matching **Term 1**, **Term 2**, or **Term 3** box in the SF9 teacher comments/remarks section, in both the workbook and print preview. The Term Grade page also provides **Download SF9** beside **Print SF9** for a direct Excel workbook download.

## PHIL-IRI reading assessments

The teacher **Phil-Iri** sidebar page has a **Results** tab with an assessment-cycle dropdown to view BOSY, MOSY, or EOSY results separately, a **Summary of Reading Level** tab with per-pupil English and Filipino progress charts, and a scoring tab for GST screening and individualized assessment. Its scoring guide follows the supplied manuals: Grades 3–6 use a 20-item GST with a 14-point cutoff; Grades 7–10 use a 40-item GST with a 28-point cutoff and a 60-minute limit. Grades outside the supplied manuals are not scored by this form. A learner below the applicable cutoff can be assessed in Oral Reading, Silent Reading, or Listening Comprehension. Oral Reading uses both word-reading accuracy and comprehension; Silent Reading and Listening Comprehension do not apply oral miscues. Timed reading modes also calculate words per minute. GST status, mode-specific results, suggested intervention, and the recommended starting passage are shown in the form and Results tab. Results are saved per pupil, cycle, test type, language, and assessment mode, and the signed-in teacher is recorded automatically as assessor. The Summary tab uses each cycle's Posttest reading level when available and falls back to Pretest; chart points and labels identify Non-reader, Frustration, Instructional, and Independent levels. English and Filipino records remain separate and appear in the corresponding PHIL-IRI class profile.

The **Download Report** button on the Phil-Iri page offers **Form 1A** (TPPK, Filipino GST) and **Form 1B** (STCRR, English GST). Each downloads an unprotected `.xlsx` filled from the saved GST results for the selected cycle, test type, and section: learners grouped by gender, test taken, overall score, below/at-or-above-cutoff marks, starting passage, and summary counts. Per-category (Literal/Inferential/Critical) scores are not collected by the app, so they are not included.

The existing PHIL-IRI workflow for Grades 4–6 also supports BOSY/MOSY/EOSY reading-level history. Configure class-specific raw-score GST passing cutoffs for each grade and language (English and Filipino). Record Pretest or Posttest GST results; a failed GST requires individualized oral or silent assessment. The portal calculates WPM, oral accuracy, comprehension, and the reading level, and supports intervention dates, recommendations, progress notes, and teacher remarks. Completed result sets autosave and can also be saved explicitly.

Class reports include reading-level summaries and Pretest/Posttest comparisons. The school consolidated report combines classes using the same School ID from Teacher Profile. Excel exports are available for class, individual learner, and school/division submission reports. Print / Save PDF uses the browser's print dialog. The school export is a generic workbook until an official division submission template is provided. PHIL-IRI data uses separate workbook worksheets and does not replace the legacy reading history.

## Attendance

Use the date-level dropdown in the attendance table to mark a date **Holiday/No Class**. This clears and locks attendance for that date across the class, displays **NC** for every learner with a light-gray background, and excludes the date from the month's class-day total. The setting persists when the month is reloaded and can be reversed by selecting **Class Day**. SF2 imports do not add attendance records on dates marked **Holiday/No Class**; imported `NC` marks are recognized as no-class dates.

The **Clear Month Attendance** button removes saved daily marks and **Holiday/No Class** dates for the selected month, after confirmation. Cleared no-class dates return to **Class Day**. Monthly learner status notes and attendance from other months are preserved.

Monthly learner statuses include a required effective date within the selected month. An **NLS** or **Transferred Out** status locks that learner's attendance beginning the next month and in all later months until the status changes to **Transferred In**. The learner remains visible in the roster and is excluded from attendance totals while locked. A **Transferred In** date excludes the learner's attendance before that date in the selected month. SF2 exports preserve the status date in the Remarks cell and show `N/A` for locked learner-days; importing the generated SF2 preserves the effective date and does not add attendance for those days.

SF2 **Average Daily Attendance** and daily gender/combined attendance totals are calculated from learners registered at the end of the selected month. NLS and Transferred Out learners are excluded from those totals, and locked `N/A` days are not counted as present.

Teachers can open **Attendance** immediately after **List of Students** in the hamburger navigation. Choose a month and year to display the DepEd School Form 2 (SF2)-style daily attendance sheet with the complete roster grouped by gender, Monday-to-Friday dates and weekdays across the page, monthly Present/Absent/Tardy counts, and monthly remarks. Saturday and Sunday are omitted from the attendance sheet. Choose Present, CC (or X) for Absent, T (Tardy), or Excused for each weekday. A reason is required for every learner marked Absent; the reason is saved and remains visible in attendance. Male, female, and combined total rows tally Present, Absent, and Tardy by weekday and for the month. Save the register to the workbook's `Attendance Records` and `Attendance Monthly Notes` worksheets; saved entries can be updated or cleared from the sheet. **Import SF2** accepts an `.xlsx` SF2 workbook with a worksheet named for the selected month (for example, `OCT 2026`) and the project template's layout. Learner names must uniquely match the teacher's roster and appear in the matching gender section. Import replaces attendance and remarks only for matching learners in the selected month; other months and roster learners omitted from the file are unchanged. Blank marks on dated weekdays mean Present; `CC` or `X` means Absent, `T` means Tardy, and `e` means Excused. Legacy `x` and `h` marks are read as Absent; legacy `l` and `t` marks are read as Tardy. Unsupported marks, unmatched names, and absent marks without a reason are rejected without changing attendance. **Download SF2** creates a separate workbook from the project's `SF2.xlsx` template for the selected month, includes the current class roster and saved attendance, clears the template's example learner rows, and hides unused learner rows so the visible roster expands or contracts to match the actual student count. It synchronizes the bottom-right gender and total enrollment, average daily attendance, and attendance percentage summaries to the current roster and attendance. Summary formulas are refreshed with matching cached values and recalculation is enabled when opened in Excel. The exported worksheet's **Displayed Month** in `AA6` and month summary in `AG117` are synchronized to the selected month, along with its date and weekday headings; attendance marks align with those dates. Its **No. of Days of Classes** total (including `AJ117`) reflects the month's weekdays, minus dates marked **Holiday/No Class**. The downloaded file is named `SF2_(Month)_(GradeLevel)_(School_Year).xlsx`, for example `SF2_January_Grade_5_2026-2027.xlsx`; set Grade and School Year in Teacher Profile first. SF2 exports and imports per-date absence reasons in the remarks cell. The template supports up to 50 learners in each gender section (100 total). Parents see attendance dates, statuses, and absence reasons for learners linked to their account in the Parent Portal; use **Refresh** in the attendance section to load the latest records while the portal is open.
Teachers can open **Attendance** immediately after **List of Students** in the hamburger navigation. Choose a month and year to display the DepEd School Form 2 (SF2)-style daily attendance sheet with the complete roster grouped by gender, Monday-to-Friday dates and weekdays across the page, monthly Present/Absent/Tardy counts, and a **Monthly Remarks** dropdown for each learner. Choose no status, **NLS - No longer in school**, **Transferred Out**, or **Transferred In**. For the SF2 **Registered Learner as of End of the Month** total, each NLS or Transferred Out status subtracts one from the roster count and each Transferred In status adds one; the beginning-of-year enrollment figures remain based on the roster. Saturday and Sunday are omitted from the attendance sheet. Choose Present, CC (or X) for Absent, T (Tardy), or Excused for each weekday. A reason is required for every learner marked Absent; the reason is saved and remains visible in attendance. Dates marked **Holiday/No Class** show **NC** for every learner with a light-gray background and are excluded from the monthly class-day count. Male, female, and combined total rows tally Present, Absent, and Tardy by weekday and for the month. Save the register to the workbook's `Attendance Records` and `Attendance Monthly Notes` worksheets; saved entries can be updated or cleared from the sheet. **Import SF2** accepts an `.xlsx` SF2 workbook with a worksheet named for the selected month (for example, `OCT 2026`) and the project template's layout. Learner names must uniquely match the teacher's roster and appear in the matching gender section. Import replaces attendance and remarks only for matching learners in the selected month; other months and roster learners omitted from the file are unchanged. Blank marks on dated weekdays mean Present; `CC` or `X` means Absent, `T` means Tardy, `e` means Excused, and `NC` means No Class for every learner on that date. Legacy `x` and `h` marks are read as Absent; legacy `l` and `t` marks are read as Tardy. Unsupported marks, unmatched names, and absent marks without a reason are rejected without changing attendance. **Download SF2** creates a separate workbook from the project's `SF2.xlsx` template for the selected month, includes the current class roster and saved attendance, clears the template's example learner rows, and hides unused learner rows so the visible roster expands or contracts to match the actual student count. It fills the School Year, Grade Level, and Section headers and the printed teacher and School Head names from the signed-in teacher's **Teacher Profile**. It synchronizes the bottom-right beginning and end-of-month enrollment counts, average daily attendance, and attendance percentage summaries to the current roster, monthly status selections, and attendance. Summary formulas are refreshed with matching cached values and recalculation is enabled when opened in Excel. The exported worksheet's **Displayed Month** in `AA6` and month summary in `AG117` are synchronized to the selected month, along with its date and weekday headings; attendance marks align with those dates. Its **No. of Days of Classes** total (including `AJ117`) reflects the month's weekdays, minus dates marked **Holiday/No Class**. The exported file is named `SF2_(Month)_(Year).xlsx` (for example, `SF2_January_2026.xlsx`). SF2 exports and imports per-date absence reasons in the remarks cell. The template supports up to 50 learners in each gender section (100 total). Parents see attendance dates, statuses, and absence reasons for learners linked to their account in the Parent Portal; use **Refresh** in the attendance section to load the latest records while the portal is open.

Teachers can open **Inventory** after **Nutritional Status** in the hamburger navigation to track classroom supplies. Add an item with its category, quantity, unit, reorder level, and notes. Items at or below the reorder level are marked **Low stock**; edits and deletions are class-scoped and saved in the workbook's `Inventory` worksheet.

Teachers can open **Summary of Grades** from the hamburger navigation to see a class-scoped table with one learner per row and subjects across columns. Use the term selector to switch between Terms 1–3. Select **Export Grading Sheet** to download the project's `Grading Sheet.xlsx` template populated with all three terms, subject final grades, and the general average. When the template contains only a `FINAL GRADES` worksheet, the export preserves it and adds a separate `SUMMARY - FINAL GRADES` worksheet formatted for the portal's term-by-term scores. The summary separates male and female learners and supports up to 50 of each; every learner must have Male or Female recorded in their profile to export. MAPEH is calculated from Music and Arts and Physical Education and Health; the displayed average is the rounded average of the eight main subjects, including MAPEH, and appears only when all eight grades are present. A dash marks a grade that has not been saved. Parents can view saved grades only for learners linked to their account.

## Reading progress

Teachers can open **Reading Progress** from the hamburger navigation. Its controls are grouped into **Reading Reports** and **Record Assessments** for easier navigation. Each period's report shows English and Filipino reading-level charts, assessment coverage, and a learner-by-learner view for that period. Use **Record BOSY**, **Record MOSY**, or **Record EOSY**, then choose an assessment attempt number (1 for the first assessment, 2 for the second, and so on) to save levels independently for that period and attempt. Saving the same period and attempt updates that attempt; other attempts remain in the history. Assessment dates are recorded automatically when saved. The available levels are Non-reader, Frustration, Instructional, and Independent; use the categories specified by your school's assessment rubric. Leave a language as Not assessed when no result is available. Results are saved in the workbook's `Reading Assessments` worksheet and are scoped to the teacher's class. Parents can view the complete dated reading assessment history only for learners linked to their account.

The Attendance page also has a **Summary Of Attendance** tab. It lists every learner currently in the roster and totals saved attendance records across months, from the earliest through the latest recorded date. Present and Tardy each add one to Present; Absent adds one to Absent. Excused and unmarked days, Holiday/No Class dates, and days locked by NLS/Transferred Out status are not counted. Use **Refresh** to reload the totals.

## Admin account management

Accounts with Admin Access have an **Admin** tab below **Teacher Profile**. The tab lists parent and teacher sign-in accounts, can enable or disable login access, and can reset another account's password. Disabling an account invalidates all of its existing sessions; re-enabling it requires signing in again. A password reset sets the temporary password to that account's email address and invalidates its existing sessions. At the next sign-in, the user must choose a different password before accessing portal data. Administrators cannot reset or disable their own account from this page.

## Nutritional Status

Teachers can open **Nutritional Status**, select the date of weighing and measurement beside **Refresh roster**, and enter each learner's weight in kilograms and height in meters. The measurement date is saved with the learner's measurements and used with the learner's sex and birthdate to calculate WHO BMI-for-age (BAZ) and Height-for-Age (HAZ) from the locally stored 5–19-year LMS reference tables. The BMI Category cell displays Severely Wasted, Wasted, Normal, Overweight, or Obese; the Height for Age (HFA) cell displays Severely Stunted, Stunted, Normal, or Tall. Results are unavailable outside the WHO reference age range of 61–228 months. Height squared (m²) and BMI (kg/m²) are calculated automatically. Use **Save and Lock** to save all changed measurements; saved rows are locked against accidental edits. Select **Unlock** to edit a saved row, then use **Save and Lock** again. **Generate SF8** becomes available when the class roster is loaded and no measurements are unsaved. It uses the selected date of assessment, builds the report from the complete class roster using the project's SF8 workbook template, and saves a copy in `downloads/generated-reports` before downloading it. Learner rows, summary counts, and signatory details are generated from the roster and profile. The report keeps the A4 landscape layout and leaves unavailable measurement cells blank; the success notice identifies the saved file and any learners with incomplete data. Empty rows prompt **Enter measurements**, and unsaved measurements prompt **Save to calculate**.

## Teacher profile

Teachers can open **Teacher Profile** from the hamburger navigation to update the name and email used by their account, position, classroom number, grade, primary section, additional **Sections handled**, **Subjects handled**, school year, Name of School, School ID, Region, Division, District, and School Head name and position. Enter handled section and subject names separated by commas or new lines. Name of School and School ID appear in generated SF2 and SF9 reports; Region, Division, and District appear in the SF9 header. Email changes apply to future sign-ins, and classroom numbers must remain unique. Class and school details are saved with the teacher's class. Teachers can change their password after verifying the current password, upload or remove a JPEG, PNG, or WebP profile picture, and upload or remove a school logo in those formats; both images are limited to 2 MB and served only to the signed-in teacher. SQLite stores the images in the local `*.profiles` and `*.profiles.school-logos` folders; Supabase stores them in PostgreSQL.

The Node test suite uses temporary SQLite databases, a mocked PostgreSQL pool, and workbook migration copies; it does not change the live database or require Supabase credentials. Run `npm run check` to parse-check the server, desktop, test, utility, and inline browser JavaScript without adding dependencies. Run the tests with `npm test`.
